1. RAG（検索拡張生成）の開発フロー
RAGは「AIに最新情報や社外秘情報を教えてから答えさせる」仕組みです。

- データの前処理（ETL）
    - PDF、Markdown、Notion、DBなどのデータを取得し、意味のある塊（チャンク）に分割します。
- ベクター化（Embedding）
    - OpenAI Ada-002 や Cohere などのモデルを使い、テキストを数値（ベクトル）に変換します。
- ベクターDBへの保存
    - Chroma, Pinecone、Supabase (pgvector)、Chroma などに保存します。
- 検索ルーチンの実装
    - ユーザーの質問をベクトル化し、DBから「内容が近い順」に情報を数件取り出します。
- プロンプト注入（Augmentation）
    - 「以下の資料に基づいて答えてください：[取得したデータ] 質問：[ユーザーの問い]」というプロンプトを生成し、LLM（GPT-4o等）に投げます。

2. AIエージェントの開発フロー
エージェントは「何をするか」をAI自身に考えさせ、ツール（関数）を実行させる仕組みです。
- ツール（Function）の定義
    - 「Googleカレンダーを取得する関数」「Notionに書き込む関数」「GitHubのIssueを作る関数」などをTypeScriptで定義します。
- 推論ループの構築（ReActパターン）
    - Thought（思考）: 何をすべきか考える。
    - Action（行動）: ツールを呼び出す。
    - Observation（観察）: 実行結果を確認する。
    - これを目的が達成されるまで繰り返すロジックを実装します。
- オーケストレーターの導入
    - LangChain.js や Vercel AI SDK (AI Core) を使い、エージェントの挙動を制御します。

3. 具体的な技術スタック（中川さんにおすすめの構成）
もし今から手を動かすなら、以下の構成が2026年のデファクトスタンダードです。
- フレームワーク: Next.js (App Router)
- AIライブラリ: Vercel AI SDK （TypeScriptとの相性が抜群で、ストリーミング処理も容易）
- データベース: Supabase （pgvectorでRAGも同時に実装可能）
- LLM: OpenAI (GPT-4o) または Anthropic (Claude 3.5 Sonnet)

4. 最初にやるべき具体的なアクション
まずは、「自分のNotion（naka note）の全データをRAGで読み込み、自分の過去の知見から答えてくれるマイAI」を作るのが一番の近道です。
- Notion APIでページ内容を取得する。
- Supabaseのベクトル保存機能に格納する。
- Vercel AI SDKで、自分のページを検索してから回答するチャットUIを作る。
この実装経験があるだけで、2026年の現場では「RAGの実装ができるエンジニア」として即戦力で重宝されます。
